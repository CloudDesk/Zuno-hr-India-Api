# 🧮 Final Settlement (FNF) - Day Calculation Technical Logic

This document provides a detailed breakdown of how days are calculated for **Unpaid Months** and **Hold Salaries** in the Final Settlement module, aligned with the core Payroll logic.

---

## 🏗️ 1. Core Logic: The "Payable Days" Formula
The system follows the standard payroll definition for payable days:

**Payable Days = (Present Days) + (Weekend Days) + (Mandatory Holiday Days) + (Approved Paid Leaves)**

*   **Present Days**: Includes statuses: `Present`, `Late`, `On-Time`, `Early-Exit`, and `Override+Present`.
*   **Half-Day Logic**: If a record has a `halfType` (First/Second Half) AND is marked `On-Leave` for the other half, it counts as **0.5 days**.
*   **Paid Leaves**: Includes `Annual Leave`, `Comp-Off`, and `Restricted Holiday (RH)`.
*   **LOP Days**: Any day within the period that is NOT covered by the above formula is considered **Loss of Pay**.

---

## 🗓️ 2. Unpaid Month Calculation (The Gap Period)

For months between the last paid payroll and the Last Working Day (LWD):

1.  **Period Boundaries**:
    *   **Standard Month**: Starts on the 1st and ends on the last day of the month.
    *   **Exit Month (LWD Month)**: Starts on the 1st and ends strictly on the **Last Working Day**.
2.  **Maximum Days**: The calculation is capped at the number of calendar days in the period (e.g., if LWD is Feb 16, max days = 16).
3.  **Algorithmic Step**:
    *   Retrieve all `AttendanceRecords` for the period.
    *   Identify `weekendDays` based on the employee's `ShiftAssignment`.
    *   Identify `mandatoryHolidays` from the assigned `HolidayCalendar`.
    *   Retrieve all `Approved` leaves.
    *   **Calculated Salary**: `(Monthly Gross / Days in Month) * Payable Days`.

## ⏸️ 3. Hold Salary Processing

For payrolls already processed but marked as **'Hold'**:

*   The FNF module does **not** recalculate days for these months.
*   It retrieves the `payableDays`, `presentDays`, and `LOPDays` directly from the existing `Payroll` record.
*   This ensures that the settlement amount exactly matches the amount that was originally held.

## 🧪 4. Implementation Notes (Bug Fixes & Alignments)

### 🚨 Critical Correction: Restricted Holiday (RH)
*   **Behavior**: When a Restricted Holiday is approved, it is stored in the `Leave` collection with `leaveType: 'restricted_holiday'`.
*   **Alignment**: The FNF logic counts all approved leaves that are NOT `LOP` as paid. Therefore, an approved RH is automatically included in `Payable Days`.
*   **Field Name Fix**: Ensure the lookup uses `userId` (Standard field in Leave model) instead of `employeeId`.

### ⚖️ LOP Consistency Fix
*   **Current State**: FNF calculates LOP by summing LOP-type leaves.
*   **Target State**: To align with Payroll, LOP should be calculated as:
    `LOP Days = (Calendar Days in Period) - (Payable Days)`
*   This captures "Unauthorized Absence" (days where the employee was absent but took no leave).
